## 07-1 · Rank-1 从 6% 拉到 48%：权重选错事故（2026-09-19）

- **背景**：07 管线首次跑通（50 query × 2000 gallery，预训练 OSNet），Rank-1 仅 6%，第一张 query 命中了陌生 pid=1014
- **干预**：不怀疑代码，先查"喂的模型对不对"——发现 `pretrained=True` 加载的是 **ImageNet 通用分类权重**，从未学过行人身份判别；换用作者团队 Market 训练版 `osnet_x1_0_market1501.pth`（hf-mirror 第三方搬运仓，567 参数全匹配，missing/unexpected 均空）
- **预期**：官方 model zoo 同级权重在 Market 全量 Rank-1 ≈ 80%
- **实测**：同一条管线**零改动**，仅换权重 → Rank-1 **6% → 48%**
- **归因**：管线无 bug，6% 完全是"模型没干过这行"造成的；剩余 48%→80% 的差距来自协议差异（小样本 50 张方差大、随机 gallery 可能不含正确答案、未剔除 junk、判卷口径比官方松）
- **结论**：①调试优先级：**先验模型身份，再查代码逻辑**；②"换权重前后对比"是隔离管线正确性的标准手段；③48% 属预期合理值，全量对表留给 GPU 到位后的 07B

## 07-2 · junk 过滤：预测涨了，实测没涨（2026-09-19）

- **背景**：07-1 定位出 48% 低于官方的候选原因之一：gallery 里混着 pid=-1 的 junk 图（官方协议评估时忽略），肉眼可见 `-1_c5s2`（多人+车糊一框）抢占过 top-1
- **干预**：`collect_samples` 两个循环加安检 `if pid == -1: continue`，junk 不再进袋
- **预期**（指导者口头预测）："每张被 junk 截胡的 query 白丢 2 个点"→ Rank-1 应回升
- **实测**：Rank-1 **48% → 48%**、剔除同相机 **46% → 46%，纹丝不动**
- **归因**：逐 query 核对——之前观察到的 junk 截胡案例（0001_c2s1），改前 1st=junk(0分)、改后 1st=pid91(仍0分)，**该 query 两头都不得分**；本 50 张样本里 junk 恰好只影响 2~3 名位次、不影响第 1 名归属，所以总分零变化。但 top-3 纯度肉眼可见提升（明细里 -1 全部消失）
- **结论**：**预测不等于事实，任何"改了会涨"的判断都必须跑前后对比验证**；junk 过滤的价值在 mAP/排序纯度类指标上（对 Top-1 单点影响小）——这正是"指标是协议的产物"的实感。行动：消融实验（D3）记录指标时，必须同时写清数据过滤协议，否则数字不可比

## 10-1 · MOT16 稀疏抽帧：250 帧只剩 1 个有效档案（2026-09-19）

- **背景**：MOT16-13（1080p 广角街景）接入 pipeline 做端到端验证，CPU 提速起见隔 25 帧取 1 帧（仅 10 帧）
- **干预**：检测跟踪→每 ID 挑帧→MIN_HITS=3 过滤噪声轨迹
- **预期**：该序列画面里行人不少，应能建出 5~10 人的小档案库
- **实测**：跟踪出现 15 个 ID，但命中帧数多为 1~3；过 MIN_HITS 后**只剩 1 个档案**（ID12，3 帧）。自查询命中 1/1（100%，但样本=1 无统计意义）
- **归因**：逐 ID 核对命中列表——广角镜头里每人只出现 2~3 次抽帧采样，间隔 25 帧≈1 秒，走动的人每次都"换位置换姿态"，ByteTrack 的 IoU 关联跟不上，轨迹被切碎成 1~2 帧的残片，全部低于 MIN_HITS。ID 号跳到 29/30 也证明跟踪器在反复发新号
- **结论**：**FRAME_STEP 是"算力-轨迹质量"的直接杠杆，1 秒 1 采样太稀**；真实使用应 ≤0.5 秒（CPU 1080p 全跑需接受小时级，或换 720p/更小序列先验证）。行动：GPU 到位后用 FRAME_STEP=2~3 重跑此序列，档案数量应显著回升——这一组"10 帧 vs 125 帧"本身就是跟踪质量的天然消融素材

## 08-1 · 冒烟三连败：库名猜错→CE焊死cuda→forward返回值误判（2026-09-19）

- **背景**：搭训练链冒烟（数据→前向→联合损失→反向），为 3060 Ti 到位日铺路
- **干预与实测**（三次修正）：①`torchreid.losses.WeightedTripletLoss` 报 AttributeError → Grep 该库 `__init__.py` 真实导出：只有 `TripletLoss`(内置hard mining)/`CrossEntropyLoss`；②换真名后 CE 炸 `Torch not compiled with CUDA` → 读库源码 `cross_entropy_loss.py:48`：`targets.cuda()` 硬编码（库太老的代价，见坑 1.18），CPU 冒烟改等价 `torch.nn.CrossEntropyLoss`；③`model(x)` 返回 751 维被当 512 特征乘 Linear 报形状错 → 读 `osnet.py:435-436`：训练模式返回值由 `build_model(loss=...)` 决定，`loss='triplet'` 才返回 `(logits, feat)` 双路
- **最终通过输出**：`batch=(32,3,256,128) logits=(32,751) feat=(32,512) loss(triplet+ce)=4.881+6.672`（8pid×4张保证 triplet 有 positive 对）
- **结论**：三次失败都不是"运气差"，而是同一课：**对库的猜测，用读源码终结，不用搜索碰运气**。附带产出关键事实——torchreid 的 CE 必须有 GPU，这反向坐实了阶段 2 非 CUDA 不可（坑 1.18）。行动：消融 A0~A3 组设计写入 docs/training_plan.md，GPU 日零决策执行

## 07B-1 · GPU 全量评估：99.61% 虚高与 92.16% 真实（2026-09-28，阶段 1B 验收）

- **背景**：3060 Ti 到位、CUDA torch 点亮（坑 1.20）后，07 管线升全量：3368 query × 19732 gallery，官方协议规模
- **干预**：两处 GPU 化（`model.eval().cuda()` + `imgs.cuda()`）——此前 torch 有 CUDA 但代码没写 `.cuda()`，一直在 CPU 跑（"cuda.is_available()=True ≠ 在用 GPU"，验证法：`next(model.parameters()).device` 或跑时开 `nvidia-smi` 看显存占用）
- **预期**：官方 Model Zoo（2026-09-28 已核实原文）osnet_x1_0 market 版标准协议 **Rank-1 94.2 / mAP 82.6**（euclidean 距离、random_flip）
- **实测**：**Rank-1(含同相机) 99.61% / Rank-1(剔除同相机) 92.16%**，GPU 数分钟完成（CPU 同规模需 1 小时+）
- **归因**：92.16% 与官方 94.2% 差 2pp，两处协议差异可解释：①我们用的权重来自第三方搬运仓（MYerassyl，训练配方未知、非官方 zoo 文件）；②我们用余弦距离+L2归一化，官方该行为 euclidean。7 个点差距全来自同相机白送分：明细 query1 的 top-1 是 cam=1 连拍重复帧 sim=0.9609；query2 的 top-1 被 pid=0 distractor 以 0.7416 抢占——9 月 18 日学的"同相机剔除/困难负样本"两条协议规则被数据实锤
- **结论**：**阶段 1B 验收通过**（92.16% ≥ 80% 验收线），评估管线可信、具备开训基准。行动：当日启动 A2 组 70 轮训练；README 指标表回填"预训练 OSNet Rank-1 92.2%（剔除同相机协议；官方 zoo 同权重 94.2%）"。教训：**对照数字必须先查一手来源**——本条初稿曾误写"官方 91.1%"（凭印象），核实 Model Zoo 原文后修正

## A2-1 · 主训练 70 轮完成：93.7 / 80.6，双指标过线（2026-09-28）

- **配置**：官方 amsgrad 配方基座 + triplet+CE 联合（loss.name triplet, weight_x 1.0），batch 64，70 轮，fixbase 10，stepsize 60，耗时 1:34:54
- **曲线**（mAP / Rank-1）：ep10 4.0/13.6 → ep20 66.5/87.1 → ep30 69.3/88.5 → ep40 70.9/88.8 → **ep50 64.9/85.8（回落）** → ep60 74.6/90.4 → **ep70 80.6/93.7（跃升）**
- **归因**：ep10 低=fixbase 冻结主干（配方设计）；ep50 抖=高 lr+增广+hard mining 采样噪声的固有震荡；ep70 冲=stepsize[60] 触发 lr÷10 精修红利
- **对标**：官方 Model Zoo 同配方 150 轮 = 94.2/82.6；我们 70 轮即 93.7/80.6，基本持平
- **验收**：线 Rank-1≥85% / mAP≥65% → **双过线，A2 签收**。checkpoint 归档 `models\osnet_market_A2_20260928.pth`（41.5MB；旁证：ep10 档仅 15MB——fixbase 期优化器只有分类头的状态，解冻后全参数动量入档体积翻倍）
- **行动**：①用 A2 权重重跑 07B 全量评估（预期 ≥94%）②A0/A1 对照消融各 ~1.5h ③B 组检索消融（11/12 换权重）

## A0-1 · 纯 softmax 对照：93.8/81.5，略胜联合损失（2026-09-29）

- **配置**：与 A2 唯一差异 = 损失换纯 softmax（删 triplet 三项覆盖）；batch 64、70 轮、fixbase 10、stepsize 60 全同；耗时 1:15:58
- **曲线**（mAP / Rank-1）：ep10 4.0/13.6（与A2同，fixbase 冻结期）→ ep20 65.7/86.2（主干解冻跃升）→ ep30 67.5/87.4 → ep40 68.9/87.9 → ep50 72.7/90.4 → ep60 73.8/90.0 → ep70 81.5/93.8；七张评估截图存 docs/figures/A0/（ep10~ep70）
- **实测**：**Rank-1 93.8 / mAP 81.5**，略高于 A2（93.7/80.6）——联合损失在默认 RandomSampler 下无增益
- **归因（源码核实）**：triplet.py 官方示例注明 triplet 需 RandomIdentitySampler（同 ID 成组进 batch，"this is important"），而 amsgrad 基座默认 RandomSampler → 随机 batch 同 ID 样本稀疏，hard-mining 挖不出有效三元组，triplet 梯度近似噪声。旁证：A2 的 ep50 回落（64.9/85.8）而 A0 同期在涨（72.7/90.4），曲线平滑度差异与"噪声梯度搅动"假设一致
- **结论**：消融说真话比预设结论值钱。行动：①A1 用 triplet 正统采样器 RandomIdentitySampler 跑纯 triplet 对照（main.py:92-94 断言：weight_x=0 时强制 fixbase_epoch=0，已验证）②增补 A2b = 联合 + RandomIdentitySampler 验证修正假设 ③系统权重由 07B 换权重复评按 mAP 在 A0/A2 间择优，不凭预设 ④收尾大纲（任务#25）须贴 docs/figures 截图逐图讲解

## A1-1 · 纯 triplet 对照：73.0/86.5，终点垫底但起点最高（2026-09-29）

- **配置**：loss=triplet（weight_x=0）、sampler=RandomIdentitySampler（triplet 正统采样）、fixbase_epoch=0（main.py:92-94 断言强制）；其余同 A0/A2；耗时 1:50:39（比 A0 慢：全参数从第1轮开训 + RandomIdentitySampler 的组采样开销）
- **曲线**（mAP / Rank-1）：ep10 57.2/77.6 → ep20 61.5/81.3 → ep30 62.0/80.8 → ep40 65.9/83.8 → ep50 64.7/82.4 → ep60 65.4/82.3 → ep70 73.0/86.5；七张截图存 docs/figures/A1/
- **实测**：**Rank-1 86.5 / mAP 73.0**——终点三组垫底；但 ep10 起点 77.6/57.2 远高于 A0/A2 的 13.6/4.0
- **归因**：起点高=fixbase=0，主干从第1轮就在学习（A0/A2 前10轮主干冻结）；终点低=纯 triplet 无分类监督兜底，特征空间只靠相对距离塑形，缺少"身份锚点"，70轮不足以收敛到 softmax 级判别力。ep30/ep50/ep60 连续三段平台+微跌，正是缺锚点时 hard-mining 梯度噪声无约束的表现
- **结论**：三组齐两行的诚实排序：**A0(81.5/93.8) > A2(80.6/93.7) > A1(73.0/86.5)**。softmax 监督是当前配方的主引擎，triplet 单独不够、联合也未超——与 A0-1 的采样器假设互为表里。行动：①A2b（联合+RandomIdentitySampler）验证"给 triplet 正确采样后联合能否反超" ②消融表 docs/ablation_results.csv 已建并填三行 ③收尾大纲逐图讲解素材齐 A0+A1 两组

## A2b-1 · 联合+身份采样：假设被证伪，最优快照在 ep40（2026-09-29）
- **配置**：同 A2 但 sampler=RandomIdentitySampler；fixbase=10（日志含 Only train ['classifier'] 行，配置核验通过）；耗时 1:29:38
- **曲线**（mAP / Rank-1）：ep10 4.0/13.6 → ep20 70.2/88.4 → ep30 71.1/88.7 → **ep40 78.8/92.1（峰值）** → ep50 76.5/91.1 → ep60 66.6/85.3（深谷）→ ep70 77.0/91.7；七张截图存 docs/figures/A2b/
- **归因**：①每 10 轮评估为单次快照带噪声；②真实工作的 triplet+hard-mining 梯度方差大，曲线比 A0 锯齿；③ep40 后训练损失仍降但泛化回吐=轻微过拟合；④ep60 深谷叠加 stepsize[60] 的 lr 衰减过渡震荡
- **工程结论**：**最后 checkpoint ≠ 最好 checkpoint**——A2b 应选用 tar-40（78.8/92.1）而非 tar-70（77.0/91.7），每 10 轮存盘纪律兑现为 +1.8 mAP
- **关键证伪**："采样器是 A2 输给 A0 的根因"假设不成立——A2b 最优 78.8/92.1 未超 A2(80.6/93.7) 更未超 A0(81.5/93.8)。诚实结论：70 轮+本配方下 triplet 一路为净负担，**纯 softmax 最优**；官方 triplet 配方出好成绩依赖其 150 轮与独立 lr 调度，损失函数价值依赖训练时长
- **结论**：四组排序 A0 > A2 > A2b > A1。行动：①系统权重以 07B 换权重复评实测排序为准（A0/A2/A2b 三候选，各用其最优快照）②答辩素材："假设→实验→证伪→修正"完整闭环比四组全赢更有说服力

## 14-2 · 分档阈值以人工真值校准：A1 精确还原 5 人（2026-10-01）
- **背景**：14-1 中 A1 零合并，疑为固定阈值 0.90 对远景素材过严。用户提供关键真值：**A1 实际只出现 5 个不同的人**（9 个 ID 中 5 组碎片 + 4 个独立）

- **实测**：**A1 9→5 组，与人工真值完全一致**（[11,50,69]、[43,95]、[68,150]、[124]、[125]；ID124↔ID125 sim=0.917 但重叠 4.48s，正确判为两人）；A2 13→9、A3 37→22、A4 2→1

- **结论**：①**阈值不能凭直觉定，要有人工真值做校准**——用户肉眼数的"5 个人"是本次唯一可用的 ground truth，A1 因此从失败案例变成校准基准；②阈值须随素材尺度（框高）自适应，单一全局值在多素材场景必失配；③并查集类合并的判据必须校验"组内全量两两关系"，只校验触发合并的那一对会留下传递漏洞

## 14-5 · 尺度判据落地：框高比>1.5 时改看 mean，误合并精确拦下（2026-10-01）
- **背景**：用户判定 14-4 的 merged_102（ID002+ID596）"不是同一个人"，其余 14 组均确认正确——共 30 对人工标注（29 对 + 1 错），成为合并模块唯一可用的 ground truth
- **分界扫描（先验证再动手）**：单用 max 无法分开（错误对 0.852 落在正确对区间 0.808~0.988 内，按它设阈误伤 6 对）；单用 mean 仍误伤 1 对（A1 ID68+ID150 mean=0.665，但框高比仅 1.06）；**组合规则"框高比>1.5 时要求 mean≥0.72"零误伤**——错误对 mean=0.707 被拦，正确对中框高比>1.5 者 mean 最低 0.732
- **原理**：max 融合只取最像的一对帧，易被校服/同款背包等偶然相似欺骗；尺度悬殊（远景 196px↔近景 393px，框高比 2.01）时视角与分辨率都变，max 更不可信，故要求"整体都像"（mean）。注意该判据仅用于**合并**；查询端融合仍用 max（召回优先），二者目标不同
- **实测**：A3 37→24 人，`拒绝 ID2+ID596（框高比2.01>1.5 且 mean=0.707<0.72）`、`拒绝 ID50+ID285（框高比2.66 且 mean=0.666）`；ID596 独立成 ID2496，原组变为 [ID002,ID366]（sim=0.835、框高比1.13，判据通过，AI 初判同人：同浅蓝短袖+黑双肩包，待用户最终确认）。四段终值：A1 5 / A2 9 / A3 24 / A4 1
- **加严未误伤**：A1 仍 5 组（其 5 条边 sim 0.808~0.891 均高于 0.80 档、框高比≤1.5 不受尺度约束）；A2 仍 9 组（ID1+ID29 框高比 4.65 但 mean=0.769>0.72，正确保留）
- **结论**：①**先做分界扫描再选判据**——三种候选规则用 30 对标注数据实测误伤数后才定案，避免了"凭直觉加约束破坏已验证真值"；②max 与 mean 是目标不同的两把尺：合并要精确（怕误并），查询要召回（怕漏检），不可混用；③人工真值哪怕只有 30 对也足以校准阈值——质检环节的人力投入直接转化为算法可靠性
